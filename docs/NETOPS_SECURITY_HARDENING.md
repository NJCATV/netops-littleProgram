# 网管小程序与 JSCN-233 / JSCN-236 安全加固清单

## 已在代码中落实

- BOSS 用户模块只允许 `super_admin`，普通用户和组织管理员前后端均拒绝。
- BOSS 查询前必须用当前登录密码二次验证，敏感授权只在内存中保留 5 分钟，页面隐藏或退出即清空。
- BOSS 列表只返回脱敏姓名、账号、电话和地址；完整资料必须逐条查看。
- BOSS 查询、详情、导入、授权成功/失败均写入 `operation_logs`，查询关键字只记录 SHA-256 摘要。
- BOSS 查询限制每页最多 20 条、至少 4 个有效字符、禁止 SQL LIKE 通配符，并按用户/IP限流。
- ONU 查询增加最小关键字长度、每分钟限流和单次最多 30 条，降低批量枚举风险。
- 登录失败按账号+IP及IP维度限流；停用账号与密码错误使用相同外部提示。
- 新密码至少 12 位并覆盖四类字符中的三类；新密码使用 `scrypt`，历史哈希仍可兼容校验。
- 新建/重置用户改用不可预测的随机临时密码，不再由手机号推导。
- 小程序不再保存明文登录密码，只保留有时效的 Bearer Token。
- 默认 Token 有效期由 7 天缩短为 8 小时；生产环境禁止使用默认 Flask/JWT 密钥。
- CORS 改为环境变量白名单，API 默认 `no-store`，补充防嗅探、防框架嵌入等响应头。

## JSCN-233 上线核对

1. 先备份当前 `.env`、Nginx 配置和已部署的 `netops2026.py`。
2. 配置两个不同的随机密钥：`SECRET_KEY`、`JWT_SECRET_KEY`，建议各不少于 32 字节。
3. 配置 `APP_ENV=production`、`JWT_ACCESS_TOKEN_EXPIRES=28800` 和精确的 `CORS_ORIGINS`；不要使用 `*`。
4. 将 Flask/Gunicorn 只绑定 `127.0.0.1:7001`，公网仅开放 Nginx 的 HTTPS 入口。
5. Nginx 必须覆盖客户端 IP：`proxy_set_header X-Forwarded-For $remote_addr`，避免伪造转发头绕过登录限流。
6. 对 `/wx/api/auth/login`、`/wx/api/netops2026/onu/search`、`/wx/api/netops2026/boss/` 分别配置严格的 `limit_req_zone`；BOSS 建议 5r/s 以下并限制突发量。
7. MySQL `6603`、Redis `6379`、Flask `7001` 不直接暴露公网；Redis 绑定回环地址并启用认证或 Unix Socket。
8. SSH 禁止 root 登录；确认密钥登录可用后再关闭密码登录，并启用 fail2ban。
9. UFW 默认拒绝入站，仅允许管理网段 SSH、业务 HTTPS 端口及明确的内网依赖。
10. 部署 `ops_platform_api.py` 到 `backend/app/routes/netops2026.py`，运行菜单初始化并重启 API；验证非超级管理员访问 BOSS 接口得到 403。

## JSCN-236 上线核对

1. 采集器进程使用独立低权限系统用户，运行目录、配置和日志按最小权限设置。
2. MySQL 数据账号只授予采集所需库表权限，不使用 root，不允许任意来源连接。
3. 采集代理端口只允许 JSCN-233 管理地址访问，并轮换 `COLLECTOR_AGENT_TOKEN`。
4. SNMP 团体号、数据库密码、代理 Token 只放服务器私有配置，权限建议 `0600`，不得写入 Git 或日志。
5. UFW 默认拒绝入站；仅开放来自 233 的管理/代理访问和明确的 SSH 管理网段。
6. 对采集器二进制和 systemd 服务设置重启限制、资源上限、`NoNewPrivileges=true`、`PrivateTmp=true`。
7. 检查日志中不输出 SNMP 团体号、数据库 DSN、Bearer Token、BOSS 用户完整资料。
8. 保留部署前二进制和配置备份，升级后核对 OLT/CMTS 采集、ClickHouse 写入及失败重试。
